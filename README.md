# AgTech Fields GIS — Веб-застосунок для управління полями

Сучасний клієнтський веб-застосунок для управління сільськогосподарськими полями та моніторинговими точками на інтерактивній карті Leaflet. Розроблено відповідно до технічного завдання для Frontend Engineer з використанням архітектурної методології **Feature-Sliced Design (FSD)**.

---

## 🚀 Швидкий старт та інструкція запуску

### Вимоги:
* **Node.js:** v18+ (рекомендовано v20 або вище)
* **npm:** v9+

### Встановлення та запуск:
```bash
# 1. Клонувати репозиторій (або перейти в папку проєкту)
cd tst-tsk

# 2. Встановити залежності
npm install

# 3. Запустити локальний сервер розробки
npm run dev
```

Після запуску відкрийте браузер за посиланням: `http://localhost:5173`

### Перевірка якості коду та збірка:
```bash
# Перевірка типів та лінтер
npm run lint

# Продакшн збірка
npm run build
npm run preview
```

## 🛠 Використані технології

* **Core & Build:**
  * **React 19 & TypeScript** — строгий режим типізації (`strict: true`, жодного `any`), компонентний підхід.
  * **Vite** — швидка збірка (HMR, ESM, оптимізований Vendor Chunks Code-Splitting).
* **Картографія та GIS:**
  * **Leaflet & React-Leaflet** — інтерактивна мапа, рендеринг шарів GeoJSON, підтримка кількох підкладок (схема + супутник), керування зумом і фокусуванням (`fitBounds`, `flyTo`).
  * **@turf/boolean-point-in-polygon & @turf/helpers** — перевірка знаходження точки строго всередині контуру обраного поля (Ray-Casting під капотом).
  * **mgrs** — перерахунок координат WGS 84 у військову систему координат MGRS на клієнті.
* **Управління станом та Форми:**
  * **Zustand** — атомарні стори без prop-drilling та зайвих ререндерів (поля, точки, модалка додавання точки, сповіщення Toast, активна вкладка навігації).
  * **react-hook-form** — декларативна валідація, керування станом форм та сабмітом без зайвих ререндерів.
  * **LocalStorage persistence** — автоматичне збереження створених та імпортованих точок між сесіями браузера.
* **UI/UX, Семантика та Доступність:**
  * **Семантичний HTML5** — повна семантична розмітка (`<aside>`, `<main>`, `<nav>`, `<header>`, `<footer>`, `<section>`, `<article>`, `<search>`, `<fieldset>`).
  * **@radix-ui/react-dialog** — доступні модальні діалоги WAI-ARIA з focus trap, restore focus та React Portal.
  * **Tailwind CSS v4** — сучасна утилітарна стилізація, адаптивність.
  * **lucide-react** — векторні іконки.

## 🏗 Архітектура: Feature-Sliced Design (FSD)

Проєкт структуровано за методологією **Feature-Sliced Design** для забезпечення слабкої зв'язності (loose coupling), ізоляції бізнес-логіки та масштабованості:

```
src/
├── app/                      # Точка монтування App, провайдери та глобальний Toast-контейнер
├── pages/
│   └── map/                  # Сторінка карти: композиційний шар робочого простору (aside, main, nav)
├── widgets/
│   ├── field-map/            # Інтерактивна карта (Leaflet, полігони, маркери, камера, події)
│   └── management-sidebar/   # Бокова панель (список полів, фільтри, список точок, імпорт/експорт)
├── features/
│   ├── add-point/            # Сценарій додавання точки (модалка, react-hook-form, useAddPointModalStore)
│   ├── filter-points/        # Пошук, фільтрація за категоріями, сортування за датою
│   ├── toggle-basemap/       # Перемикання підкладки (Схема Voyager ↔ Супутник Esri)
│   ├── export-points/        # Експорт/Імпорт точок (GeoJSON, CSV), парсер файлів та вивантаження
│   └── reset-demo-data/      # Скидання до початкових демонстраційних точок
├── entities/
│   ├── field/                # Сутність поля (GeoJSON модель, useFieldStore, картка поля)
│   └── point/                # Сутність точки (модель, usePointStore, SVG-маркер, попап, картка)
└── shared/                   # Перевикористовуваний інфраструктурний код
    ├── lib/                  # Гео-утиліти (MGRS, Turf Point-in-Polygon), форматування дат
    ├── config/               # Конфігурації типів замірів та картографічних підкладок
    ├── model/                # useNavigationStore (активна вкладка на мобільних пристроях)
    └── ui/                   # Базовий UI-Kit (Modal на Radix UI Dialog, Toast з useToastStore)
```

## 🏛 Прийняті інженерні та архітектурні рішення

1. **Сувора семантична розмітка HTML5 та доступність (Accessibility / WAI-ARIA):**
   * Замість несемантичних `<div>` застосовано нативні теги стандарту HTML5:
     * `<aside aria-label="...">` для бокової панелі управління;
     * `<main aria-label="...">` для основної робочої області карти;
     * `<nav aria-label="...">` для мобільної панелі перемикання вкладок;
     * `<header>` та `<footer>` для структуризації діалогів, попапів та карток;
     * `<section aria-labelledby="...">` та семантичні списки `<ul role="list">` / `<li>` для полів і замірів;
     * `<article>` для карток полів та точок з підтримкою клавіатурної взаємодії (`tabIndex`, `onKeyDown`, `aria-label`);
     * `<search role="search">` зі прихованим доступним `<label>` для скринрідерів.

2. **Декларативне управління формами через `react-hook-form`:**
   * Форма додавання точки в `CreatePointModal` переведена на `react-hook-form`.
   * Декларативна валідація довжини опису (до 250 символів) та обов'язковості типу замірy.
   * Виведення помилок з `role="alert"` та `aria-invalid`, автоматичне скидання форми `reset()` при закритті діалогу та відображення індикатора `isSubmitting`.

3. **Оптимізація розміру бандла (Code Splitting):**
   * У конфігурації Vite налаштовано функцію `manualChunks`, що розділяє важкі сторонні бібліотеки на незалежні кешовані чанки:
     * `gis-vendor` (~173 kB): Leaflet, React-Leaflet, Turf.js, MGRS;
     * `react-vendor` (~285 kB): React 19, Radix UI, React Hook Form, Zustand;
     * Основний бандл застосунку зменшено до компактних **~43 kB**!

4. **Усунення Prop Drilling через атомарні стори Zustand:**
   * Стан відкриття форми додавання точки інкапсульовано у `features/add-point/model/useAddPointModalStore`. Клік на карті або по активному полю відкриває модалку напряму.
   * Централізований `shared/ui/Toast/model/useToastStore` дозволяє будь-якому модулю програми показувати сповіщення (`error`, `success`, `info`) без наскрізного прокидання колбеків.
   * `shared/model/useNavigationStore` синхронізує активну вкладку на мобільних пристроях при виборі точки або поля у сайдбарі.

5. **Доступність (a11y) та модальні вікна через `@radix-ui/react-dialog`:**
   * Повна відповідність специфікаціям WAI-ARIA (`role="dialog"`, `aria-modal="true"`, зв'язування `DialogTitle` та `DialogDescription`).
   * Надійний **Focus Trap** (клавіатурний фокус замкнений у діалозі, виключаючи випадкові кліки по карті під оверлеєм) та автоповернення фокусу при закритті.
   * Рендеринг через **React Portal** у корінь `document.body`, що усуває конфлікти зі стеком шарів (`z-index`) Leaflet.

6. **Адаптивна контрастність контурів полів на супутникових знімках:**
   * На світлій векторній підкладці Voyager контури мають акуратний темний колір (`#475569`, 1.5px).
   * При перемиканні на темні фотознімки Esri World Imagery контури автоматично стають контрастними світлими (`#f8fafc`, 2px, чіткий пунктир `6, 6`, легка біла підкладка `0.14`), а активне поле виділяється яскравим неоново-ізумрудним контуром (`#34d399`, 3.5px).
   * Оновлення стилів здійснюється на льоту через `layer.setStyle()`, що забезпечує 60fps без перемальовування карти.

## 🌟 Робота з даними: Імпорт, Експорт та Демо-файли

У проєкті реалізовано повноцінне двостороннє управління даними моніторингових точок:

### 📥 1. Експорт даних:
* **GeoJSON (.geojson):** стандартна геопросторова колекція `FeatureCollection` (RFC 7946) з геометрією `Point` та розширеними властивостями (`id`, `fieldId`, `type`, `mgrs`, `description`, `createdAt`).
* **Таблиця Excel (.csv):** структурований CSV з підтримкою UTF-8 BOM для автоматичного коректного відкриття в Microsoft Excel та Google Sheets без проблем з кодуванням.

### 📤 2. Імпорт даних з файлу:
* У випадаючому меню кнопки **«Дані»** доступна дія **«Імпортувати GeoJSON / CSV»**.
* Клієнтський парсер автоматично:
  * Розпізнає координати WGS 84 (`lat`, `lng`).
  * Перевіряє прив'язку точки до полів за допомогою алгоритму Turf Point-in-Polygon.
  * Якщо координата MGRS не заповнена, вона автоматично розраховується на льоту.
  * Розпізнає типи замірів як за кодами (`SOIL_SAMPLE`, `PESTS`...), так і за українськими назвами.

### 📁 3. Мокові файли для тестування (Samples):
У проєкті підготовлено 2 еталонні файли з реальними координатами всередині тестових полів:
* [`samples/monitoring-points-sample.geojson`](./samples/monitoring-points-sample.geojson) — еталонний GeoJSON-набір.
* [`samples/monitoring-points-sample.csv`](./samples/monitoring-points-sample.csv) — еталонна CSV-таблиця.

> **💡 Швидке тестування в інтерфейсі:**  
> У випадаючому меню кнопки **«Дані»** натисніть пункт **«Завантажити демо-зразок»** — застосунок автоматично завантажить та відобразить на карті 6 зразкових точок замірів по всіх 4 полях за 1 клік!

## 📋 Обґрунтовані припущення (Assumptions)

1. **Клієнтський рівень збереження даних:** Використано `localStorage` для збереження стану між перезавантаженнями браузера, з початковими мок-даними.
2. **Точність гео-обчислень:** Точки WGS 84 округлюються до 6 знаків (~10 см). Координати MGRS формуються з точністю 1 м (точність 5) та блоковим форматуванням.
3. **Логіка взаємодії з картою:**
   * Клік по неактивному полю робить його активним та центрує камеру.
   * Клік по вже активному полю відкриває модальне вікно створення нової точки.
   * Клік за межами полів викликає інформативне Toast-сповіщення про помилку.

## 🎯 Підготовка до технічного інтерв'ю (FAQ до захисту)

* **Чому Feature-Sliced Design (FSD)?**
  * Забезпечує слабку зв'язність: сторінка `MapPage` виступає композитором, фічі ізольовані, відсутні циклічні залежності.
* **Чому Zustand для модалок і Toast?**
  * Усуває prop drilling, не викликаючи зайвих перемальовувань Canvas-шару мапи при введенні тексту чи зміні стану діалогів.
* **Чому Radix UI Dialog та react-hook-form?**
  * Промисловий стандарт доступності (WAI-ARIA, Focus Trap, Escape handling, React Portal) та легкі контрольовані форми з мінімальним оверхедом по ререндерах.
* **Чому Turf.js boolean-point-in-polygon?**
  * Надійний алгоритм Ray-Casting для перевірки належності точки контуру обраного поля.
