# AgTech Fields GIS — Веб-застосунок для управління полями

Сучасний клієнтський веб-застосунок для управління сільськогосподарськими полями та моніторинговими точками на інтерактивній карті Leaflet. Розроблено відповідно до технічного завдання для Frontend Engineer з використанням архітектурної методології **Feature-Sliced Design (FSD)**.

---

## 🚀 Швидкий старт та інструкція запуску

### Вимоги:
* **Node.js:** v18+ (рекомендовано v20 або вище)
* **npm:** v9+

### Встановлення та запуск:
```bash
# 1. Клонувати репозиторій (або перейти в папку проєкту)
cd tst-tsk

# 2. Встановити залежності
npm install

# 3. Запустити локальний сервер розробки
npm run dev
```

Після запуску відкрийте браузер за посиланням: `http://localhost:5173`

### Перевірка якості коду та збірка:
```bash
# Перевірка типів та лінтер
npm run lint

# Продакшн збірка
npm run build
npm run preview
```

## 🏗 Архітектура: Feature-Sliced Design (FSD)

Проєкт структуровано за методологією **Feature-Sliced Design** для забезпечення слабкої зв'язності (loose coupling), ізоляції бізнес-логіки та масштабованості:

```
src/
├── app/                      # Глобальні стилі, провайдери, точка монтування App
├── pages/
│   └── map/                  # Сторінка карти: компонування робочого простору
├── widgets/
│   ├── field-map/            # Інтерактивна карта (Leaflet, полігони, маркери, камера)
│   └── management-sidebar/   # Бокова панель (список полів, фільтри, список точок, дії)
├── features/
│   ├── add-point/            # Сценарій додавання точки (модалка, валідація координат)
│   ├── filter-points/        # Пошук, фільтрація за категоріями, сортування за датою
│   ├── toggle-basemap/       # Перемикання підкладки (Схема Voyager ↔ Супутник Esri)
│   ├── export-points/        # Експорт точок у формати GeoJSON та Excel/CSV
│   └── reset-demo-data/      # Скидання до початкових демонстраційних точок
├── entities/
│   ├── field/                # Сутність поля (GeoJSON модель, store, картка поля)
│   └── point/                # Сутність точки (модель, store, SVG-маркер, попап, картка)
└── shared/                   # Перевикористовуваний інфраструктурний код
    ├── lib/                  # Гео-утиліти (MGRS, Turf Point-in-Polygon), форматування дат
    ├── config/               # Конфігурації типів замірів та картографічних підкладок
    └── ui/                   # Базовий UI-Kit (Modal, Toast)
```

## 🏛 Прийняті інженерні та архітектурні рішення

1. **Розмежування осей координат (`[lat, lng]` vs `[lng, lat]`):**
   * *Проблема:* Leaflet працює з форматом `[latitude, longitude]`, тоді як стандарт GeoJSON (RFC 7946), Turf.js та бібліотека MGRS строго вимагають `[longitude, latitude]`.
   * *Рішення:* Трансформації інкапсульовані в модулі `shared/lib/geo/geo.ts`.

2. **Zustand замість Redux Toolkit або Context API:**
   * *Context API* викликає ререндеринг усього дерева мапи при кожному натисканні клавіші в пошуку.
   * *Redux Toolkit* створює надлишковий обсяг коду.
   * *Zustand* забезпечує ізольовані підписки через селектори (`useFieldStore((s) => s.activeFieldId)`).

3. **Векторні SVG-маркери (`L.divIcon`) та усунення «ковзання» маркерів:**
   * Замість дефолтних PNG Leaflet, які часто втрачаються у збірках Vite, використані динамічні SVG-маркери.
   * **Важливий фікс продуктивності:** Leaflet позиціонує маркери через `transform: translate3d(x, y, 0)`. Будь-який `transition: transform` на батьківському контейнері маркера конфліктує з 60fps позиціонуванням Leaflet, викликаючи «відставання» та «пливучий фриз» точок при зумі та польоті камери. У нашій реалізації ховер-анімація винесена на внутрішній контейнер `.custom-point-marker-inner`, що забезпечує 100% плавність.

4. **Усунення прямокутної рамки браузерного фокусу на полях:**
   * При кліку на векторні SVG `<path>` браузери на базі Chromium виділяють Bounding Box елемента прямокутною рамкою `:focus`.
   * Додано глобальне пригнічення контуру фокусу для `.leaflet-interactive` та `path:focus`. Оновлення кольору полів оптимізовано через прямий виклик `layer.setStyle()`, що усуває зайве перемотування DOM-вузлів.

5. **Розведення анімацій камери:**
   * Коли користувач обирає точку зі списку, камера виконує прямий політ `flyTo` до точки заміру без конфлікту з `fitBounds` контуру поля.

6. **Адаптивність (Desktop + Tablet / Mobile):**
   * На екранах **≥ 1024px** — двоколонковий спліт (панель керування зліва, карта справа).
   * На екранах **< 1024px** — мобільна плаваюча панель перемикання вкладок («Карта» ↔ «Поля та Точки») з автоматичним переходом до карти при кліку на точку.

## 🌟 Додатковий функціонал (понад базове ТЗ)

1. **🛰 Перемикач супутникового шару (Satellite Basemap):**
   Швидке перемикання між детальною схемою (CartoDB Voyager) та реальними супутниковими знімками високої роздільної здатності (Esri World Imagery) — стандарт де-факто для сучасного AgTech.
2. **📥 Експорт даних (GeoJSON та CSV):**
   Можливість зберегти та вивантажити список відфільтрованих точок у форматах `.geojson` (для GIS-систем та бортових комп'ютерів) або `.csv` з підтримкою UTF-8 BOM (для відкриття в Excel).
3. **🔄 Скидання до початкових демо-точок:**
   Зручна кнопка повернення до початкового стану у разі видалення або додавання великої кількості тестових маркерів.
4. **💬 Інформативні Tooltips на карті:**
   При наведенні курсору на контур поля з'являється плаваючий тултип з назвою, площею в гектарах та культурою.

## 📋 Обґрунтовані припущення (Assumptions)

1. **Клієнтський рівень збереження даних:** Використано `localStorage` для збереження стану між перезавантаженнями браузера, з початковими мок-даними.
2. **Точність гео-обчислень:** Точки WGS 84 округлюються до 6 знаків (~10 см). Координати MGRS формуються з точністю 1 м (точність 5) та блоковим форматуванням.
3. **Логіка кліків по карті:**
   * Клік по неактивному полю робить його активним та центрує камеру.
   * Клік по вже активному полю відкриває модальне вікно створення нової точки.
   * Клік за межами полів викликає інформативне Toast-сповіщення про помилку.

## 🎯 Підготовка до технічного інтерв'ю (FAQ до захисту)

* **Чому Feature-Sliced Design (FSD)?**
  * Забезпечує масштабованість проєкту: фічі (додавання точки, фільтрація, експорт) ізольовані, сутності (поле, точка) мають чіткі межі та публічні API (`index.ts`), відсутні циклічні імпорти.
* **Чому Zustand?**
  * Відсутність зайвих ререндерів: при введенні тексту в пошук оновлюється лише список у сайдбарі, карта Leaflet не перезавантажується.
* **Чому Turf.js boolean-point-in-polygon?**
  * Надійний алгоритм Ray-Casting, що коректно обробляє вгнуті контури та крайові випадки вершин полігонів.
